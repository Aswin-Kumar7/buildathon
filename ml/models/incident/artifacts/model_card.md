# Model card — card-testing risk model

Generated by `make eval`. Not hand-edited.

## What this is

The one deployed model: a temperature-scaled histogram gradient-boosted ensemble that scores an
entity's risk of being card testing / abuse, **P(abuse)**. It is exported as node arrays the request
path walks directly, so scoring needs no native runtime, and its per-feature contributions are exact
interventional values rather than approximations. The number reported here is this model's, on a
held-out split of the same corpus it was trained on — there is no separate benchmark model.

- Registry version `r1`, feature definition `fdv-bfe27ae905dd`,
  training data `sha256:b5f100ca3407d0cf`.
- 5,225 rows across 640 scenario groups; positive (abuse) rate 0.197.

## Is the corpus hard enough for any of this to count?

A model scoring well on data the project generated itself proves nothing until the data is shown not
to give the answer away. Every feature is scored alone, and the strongest is turned into the dumbest
possible model — one threshold, chosen on validation by the same cost sweep the real operating point
uses. The distance between that and the trained model is what the model actually earns.

One feature alone (log_attempts) reaches PR-AUC 0.553636; the model reaches 0.991104, a lift of 0.437468. The corpus is not separable by any single feature, so the model is earning its score from the combination rather than from a giveaway column.

## Model ladder — why this model class

A temperature-scaled logistic regression was served first, for a real engineering reason: it ran in
the request path as a handful of dot products, and its per-feature contributions were exact rather
than approximated. The ladder tested that reason instead of accepting it, on the same split, the same
cost model and the same threshold sweep — and the ensemble won by enough that continuing to serve the
linear model would have meant publishing a result and ignoring it.

| Model | PR-AUC | Precision | Recall | Brier | Cost |
|---|---|---|---|---|---|
| hist-gradient-boosting-temperature **(served)** | 0.9911 | 0.8754 | 0.9786 | 0.0173 | ₹61,200 |
| logistic-temperature | 0.9401 | 0.7215 | 0.9714 | 0.0439 | ₹124,000 |
| random-forest | 0.9882 | 0.8722 | 0.9750 | 0.0196 | ₹67,000 |

Re-split 5 ways, the served model beat `logistic-temperature` on 5 of 5 groupings — PR-AUC delta mean -0.0581 (sd 0.0111) measured from the alternative's side, so negative means the served model is ahead; mean cost change +₹56,280.

Neither half of the original argument was actually lost. The ensemble serialises to nested node
arrays that the request path walks directly, so there is still no native runtime and no ONNX. And
attribution is still exact: rather than reading a coefficient, each feature is held at its training
median and the model re-scored, which gives that feature's exact interventional contribution to *this*
prediction. Eleven walks of the ensemble cost roughly 66 microseconds, against a detection latency
measured in seconds.

## What this does not claim

- **These labels are synthetic, not real-world outcomes.** Synthetic scenario corpus, not real-world labels. Every row is an entity from a seeded scenario the project authored; the label is the scenario's ground truth, not a confirmed chargeback. Scores measure the deployed model on a held-out grouped split of this corpus. The path to real labels is the merchant's own confirmed incidents — see the retraining design.
- The model is load-bearing but leashed: it feeds the decision alongside the deterministic rules and
  arbitration, and can route a case to a person, but it never contains a shopper on its own.
- Per-origin rates are counts over small samples. Each carries its 95% Wilson interval in
  `METRICS.md`; a bare "1.000" on sixteen rows means *above 0.81*, not certainty.
